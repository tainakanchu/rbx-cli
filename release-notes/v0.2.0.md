## rbx-cli 0.2.0

Moves to [rbxport](https://github.com/chrisle/rbxport) 1.10.0 (pinned to `d0ff75b`; 0.1.x used 1.2.0). rbxport 1.10 no longer refuses a sync in two cases where 1.2 did, so the **protocol version is now `2`**: callers written for protocol 1 must review the breaking changes below.

> Not affiliated with AlphaTheta / Pioneer DJ. rekordbox and CDJ are their trademarks.
> **Not yet verified on physical players.** Check a stick on a player before relying on it at a gig.

### Breaking changes (protocol 2)

- **Cues and beat grids a player changed are now replaced, not refused.** Following rbxport (the library wins; player edits come back only through import, as in rekordbox), `options.onDeviceChanges` now defaults to `"overwrite"`. `"fail"` has been removed and is refused with `invalid_request`. `"keepDevice"` is unchanged. **If you relied on the old default to protect cues saved on a player, read them with `usb inspect --cues` before exporting, or send `"keepDevice"`.**
- **A missing source no longer fails the sync.** For a track an earlier export put on the device, rbxport now keeps the device's copy as it is. The item is reported with `items[].status: "kept"` and a warning, and the exit code is 0.
- **Conflict reasons removed:** `cues_or_grid_changed_on_device`, `onelibrary_cues_changed_on_device` and `source_unavailable`. rbxport no longer raises them.
- **New conflict reason `device_cues_on_removed_track`** (with `name` = the track's title). A player added or changed cues on a track that this sync would take off the device.
- Every envelope carries `"protocol": 2`.

### Changes

- **`kept` and `failed` items.**
  - `items[].status` gains two values:
    - `kept`: the device copy was kept because the source was unavailable or updating from it failed.
    - `failed`: the track was left out because its audio could not be read, converted or copied. The rest of the export carries on and exits 0.
  - Each comes with an `items[].warnings` entry.
  - New counts `tracks.keptExisting` and `tracks.failed`.
  - `--dry-run` reports `kept` for a missing source that the device holds.
  - Capability: `usb.export.keptAndFailedItems`.
- From rbxport 1.2 → 1.10, among others:
  - Windows reserved names (`CON`, `NUL`, …) are escaped in FAT-safe device paths.
  - A stick whose `exportLibrary.db` has out-of-range integer columns or invalid release years no longer stops the sync.
  - A library cue at a negative position no longer stops the sync.
  - rekordbox exports with `dbVersion` 10000 are accepted when the schema matches.

### For integrators

- The request and response formats are documented in [`docs/protocol.md`](https://github.com/tainakanchu/rbx-cli/blob/v0.2.0/docs/protocol.md). The breaking changes are listed under [Changes in protocol 2](https://github.com/tainakanchu/rbx-cli/blob/v0.2.0/docs/protocol.md#changes-in-protocol-2). JSON Schemas are in [`schema/`](https://github.com/tainakanchu/rbx-cli/tree/v0.2.0/schema).
- Check `protocol` in `version --json` before sending requests. A request with a newer `protocol` than the CLI's is refused (`unsupported`).
- `tracks.kept` keeps its 0.1.x meaning: tracks kept on the device although they were not requested (`prune: false`). The new count for `kept` items is `tracks.keptExisting`.

### Known limitations

- rbxport reports kept and failed tracks by title (and `id`), not by request position. rbx-cli matches a report entry to an item only when exactly one request track has that title.
  - A failed track that cannot be matched still shows `status: "failed"`, with the warning `reason not reported`.
  - On a sync after the one that first kept a device copy, the `kept` item has no `deviceId`, `devicePath` or `analysisDir`. With `--dry-run` it is reported as `skipped`.
- `keepDevice` keeps the stick's cues and grid for that sync only, as in 0.1.1.
- `composer` and `albumArtist` are still not accepted, because rbl-export does not take or write them.
