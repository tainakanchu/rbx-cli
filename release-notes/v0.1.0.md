## rbx-cli 0.1.0

First release. rbx-cli is a command-line tool for rekordbox-compatible DJ libraries, built on the crates of [rbxport](https://github.com/chrisle/rbxport) (pinned to `a029c0c`, rbxport 1.2.0).

> Not affiliated with AlphaTheta / Pioneer DJ. rekordbox and CDJ are their trademarks.
> **Not yet verified on physical players.** Check a stick on a player before relying on it at a gig.

### Features

- **`usb export`**: writes tracks and playlists (including folders) to a USB stick, both for the first export and for later incremental syncs.
  - Writes both the Device Library (`export.pdb`) and Device Library Plus / OneLibrary (`exportLibrary.db`).
  - Writes ANLZ analysis files. BPM, key, beat grid and waveforms are generated from the audio.
  - Embedded artwork, removal of stale files (`prune`), and a device name.
  - Accepts a beat grid and hot cues, memory cues and loops supplied by the caller. Supplying a grid doesn't decode the audio again.
  - `--dry-run`: shows how many tracks will be copied, reused or analysed, plus cache hits, bytes to write and free space, without writing anything.
  - Checks free space before writing.
- **`usb inspect`**: reads an existing export. Shows tracks, playlists and formats; `--cues` also shows cues saved by a player.
- **`usb verify`**: runs rbxport's export verification.
- **`devices list` / `devices eject`**: lists mounted volumes and ejects them safely.
- **`version --json`**: reports the version, the pinned rbxport revision, the protocol version and the capability list.

### For integrators

- `--json` writes NDJSON to stdout: `progress` / `event` / `log` lines, ending in exactly one `result` or `error` line. Protocol version: `1`.
- The request and response formats are documented in [`docs/protocol.md`](https://github.com/tainakanchu/rbx-cli/blob/v0.1.0/docs/protocol.md); JSON Schemas are in [`schema/`](https://github.com/tainakanchu/rbx-cli/tree/v0.1.0/schema).
- Exit codes: `0` ok, `1` error, `2` usage error or invalid request, `3` verification failed, `130` cancelled.
- Cancellation: SIGINT/SIGTERM, or a `cancel` line on stdin with `--stdin-control`.

### Performance

- **Analysis cache.** Analysis for unchanged audio is never regenerated. The cache is keyed on path, size, mtime, sampled content, the rbxport revision and the analysis settings. Changing only cues keeps every cache hit.
- Analysis runs in parallel (`-j`, default 3).
- Measured on a 4-core Linux VM:
  - a 5-minute track takes about 0.5–0.6 s to decode and analyse;
  - a re-export where every track hits the cache takes about 2 s for 8 tracks (excluding audio checks).

### Known limitations

- Re-exports read every audio file in full, on both the source and the stick, to detect changes. This is rbxport's behaviour, and it dominates re-export time on slow sticks.
- Both library formats are always written; you can't pick just one.
- Analysis finishes before copying starts; the two don't overlap yet.
- If a player changed the cues on the stick and the request supplies cues, the export stops with a `conflict` error and writes nothing. Leave cues out of the request to keep the ones on the stick.
- `usb verify` may first recover an interrupted export, which writes to the stick.
- The analysis cache is never trimmed.
