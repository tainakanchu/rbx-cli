## rbx-cli 0.1.1

Additive fixes from integrating rbx-cli into a desktop app. Still built on [rbxport](https://github.com/chrisle/rbxport) pinned to `a029c0c` (rbxport 1.2.0). Protocol version: still `1`; everything new is additive.

> Not affiliated with AlphaTheta / Pioneer DJ. rekordbox and CDJ are their trademarks.
> **Not yet verified on physical players.** Check a stick on a player before relying on it at a gig.

### Changes

- **Machine-readable conflict reasons.** `conflict` errors now carry `details.reason`, a stable snake_case string (`cues_or_grid_changed_on_device`, `source_unavailable`, `ownership`, `both_roots`, `track_changed_on_device`, … and `other` as the fallback), plus `database`, `name` and `deviceTrackId` when rbxport names them. For `usb export`, `details.tracks` lists the request tracks concerned (`index`, `ref`, `deviceId`) for `source_unavailable`, `cues_or_grid_changed_on_device` and `track_changed_on_device`. Capability: `usb.export.conflictReasons`. Schema: `schema/details.conflict.json`.
- **Keep what a player changed instead of failing.** New request option `options.onDeviceChanges`: `"fail"` (default, as before) or `"keepDevice"`. With `keepDevice`, a track whose cues or beat grid changed on the stick since the last sync keeps the stick's cues and grid (the request's `cues` / `beatGrid` for that track are ignored, with a warning), and the rest of the export goes ahead. Reported as `items[].deviceChangesKept` and `tracks.deviceChangesKept`, also in `--dry-run`. Capability: `usb.export.keepDeviceChanges`.
- **`--cancel-on-stdin-eof`** for `usb export`: the end of stdin cancels the export (implies `--stdin-control`), so an export stops when the parent process dies. `--stdin-control` on its own is unchanged (the end of stdin is still not a cancellation). Capability: `usb.export.stdinEofCancel`.

### Fixes

- `bytes.free` is no longer missing when the destination is a plain folder rather than a volume root the OS lists: it is now the free space of the filesystem holding the destination (`statvfs` on Unix, the volume's free space on Windows). The `insufficient_space` check now applies to such destinations too.

### For integrators

- The request and response formats are documented in [`docs/protocol.md`](https://github.com/tainakanchu/rbx-cli/blob/v0.1.1/docs/protocol.md) (see [Conflict reasons](https://github.com/tainakanchu/rbx-cli/blob/v0.1.1/docs/protocol.md#usb.export.conflictReasons), [Cues](https://github.com/tainakanchu/rbx-cli/blob/v0.1.1/docs/protocol.md#cues) and [Cancellation](https://github.com/tainakanchu/rbx-cli/blob/v0.1.1/docs/protocol.md#cancellation)); JSON Schemas are in [`schema/`](https://github.com/tainakanchu/rbx-cli/tree/v0.1.1/schema).
- Test for the new behaviour with `version --json` capabilities rather than the version number.
- rbl-export reports conflicts as text only, so rbx-cli derives `details.reason` by matching rbxport's messages at the pinned revision. Keep `message` for display; match on `reason`.

### Known limitations

- `cues_or_grid_changed_on_device` does not say whether the cues or the beat grid changed: rbxport does not tell them apart.
- `keepDevice` keeps the stick's cues and grid for that sync only: the next sync applies the request's cues and grid (or the analysed grid) again unless the stick changes again. Import what you want to keep (`usb inspect --cues`) first. Cue changes that exist only in `exportLibrary.db`, and every other kind of conflict, still fail.
- `composer` and `albumArtist` are not accepted yet: both library formats have room for them, but rbl-export does not take or write them.
- Unchanged from 0.1.0: re-exports read every audio file in full on both sides; both library formats are always written; analysis finishes before copying starts; `usb verify` may first recover an interrupted export; the analysis cache is never trimmed.
